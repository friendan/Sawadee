# 辅音写字动画

选中辅音卡片后，大字会按泰语笔顺“一笔一笔写出来”：黄色笔迹沿字形推进，笔尖是一个白圈黄心的圆点，写完停 1 秒再循环。代码在 `src/Sawadee/WriteGlyph.cpp`（控件 `CWriteGlyphUI`），每个辅音的笔顺数据也在这个文件里。

## 一、效果是怎么画出来的

核心思路：**笔迹的颜色永远来自字形本身，路径只决定“哪部分已经写出来”**。所以笔不可能画到字外面去，路径粗一点、偏一点都不会出现字外的黄色。

每帧 `PaintText` 做这几件事：

1. **取字形轮廓**：用 DirectWrite `CreateGdiCompatibleTextLayout` 排版单个字符（字体 `TH Sarabun New`，字号取控件字号，默认 88），自定义 `IDWriteTextRenderer`，在 `DrawGlyphRun` 里调用 `GetGlyphRunOutline` 拿到字形的 `ID2D1Geometry`，再平移到基线位置。得到的几何体已经是屏幕坐标、y 向下，**不要再做 `Scale(1,-1)`**。
2. **墨迹框**：`glyph->GetBounds()` 得到字形外接矩形 `ink`。笔顺坐标都相对这个框定义。
3. **底色**：用文字颜色 `FillGeometry(glyph)` 画出完整的灰底字。
4. **写出部分（遮罩）**：`BuildWritingMask` 按当前进度 `t` 截取笔顺折线，用圆头、圆角的笔 `Widen` 成一块面积，作为 `PushLayer` 的几何遮罩，然后用主题色 `color-warning`（黄）再 `FillGeometry(glyph)` 一次。被遮罩盖住的字形部分变黄，其余保持灰底。
5. **笔尖**：`0 < t < 1` 时在当前笔尖位置画两个同心圆：外圈半径 `nib*0.55` 用文字色，内圈半径 `nib*0.32` 用黄色。`t = 1` 时不画笔尖。

时序：每 32ms 刷新一次；写 3000ms（`kWriteDurationMs`），停 1000ms（`kWriteHoldMs`），循环直到取消选中（`StopWriting`）。刷新不能用窗口的 `SetTimer` / `WM_TIMER`，见第七节。

进度按**弧长**分配：先累加整条路径所有线段长度 `total`，`remain = t * total`，逐段推进，最后一段按比例插值出笔尖点。所以长笔画写得久、短笔画写得快，速度均匀。

## 二、笔顺数据格式

```cpp
const Pt kNoNu[] = { {22,29},{14,26},...,{88,4},{-2,-2} };
```

- 坐标是墨迹框内的归一化值 **0–100，y 向下**：`x = ink.left + x/100 * 宽`，`y = ink.top + y/100 * 高`（`MapX` / `MapY`）。
- `{-2,-2}` 表示路径结束。
- `{-1,-1}` 表示提笔：结束当前一笔，下一个点开始新的一笔，提笔之间不计入弧长，也不会画连线。大多数辅音是**一笔写完**，只有 ส、ศ、ษ、ญ、ฐ 等确实要提笔的字才用。
- 点的顺序就是书写顺序，相邻两点之间是直线。弯的地方多放几个点即可，不需要很密，30–40 个点足够一个字。

`kPaths[]` 表里每个字符对应一条路径和一个笔宽系数：

```cpp
{ L'น', kNoNu, 0.09f },
```

## 三、笔宽

```
thickness = max(floor, 墨迹框高度 * 笔宽系数)
```

- 笔宽系数在 `kPaths[]` 里按字单独设，大多在 0.08–0.12。
- `floor` 是最小笔宽（`BuildWritingMask` 里的 `minThick`，以及笔尖的 `minNib`，两处名单必须一致）：ส 为 2，ศ ค ฅ ฆ ง ช ซ ฌ ญ ฑ ณ 为 7，其余为 5。
- 字号 88 时墨迹框高约 36 像素，绝大多数字最终笔宽是 5 像素（半径 2.5）。
- 笔宽不是越粗越好：遮罩太粗，会在写前一笔时就把旁边后写的笔画提前染黄（用户看到的就是“后面的笔画提前写了一小段”）。

## 四、笔顺规则（用户验收过的经验）

1. **有圆圈（หัว）的字从圆圈起笔**，起点放在圆圈和竖笔/主体的交接处，落在圆圈一侧。先写完整圈，再接主体。
2. **圆圈方向按字定**，不是统一的：
   - 顺时针：ฆ（两个圈）、ญ 第一个圈、ฑ、ณ 两个圈、ล（官方写法）、ม 的下圈。
   - 逆时针：ย、ร、ว、ฬ 右上圈、ฮ（同 อ 的官方写法）、ภ、ญ 第二笔。
   用户点名要求的方向优先。
3. **没有圆圈的字**（ก、ธ）从字的底部或左中起笔，按官方描述走。
4. **一笔写完**：不能来回刷同一段，不能从一处“跳”到另一处空白。字形本身的折角（脚尖、尖顶、底部 V 形）是允许的掉头。
5. **只走在笔画上**：笔尖中心不能离开字形，否则用户看到“没有笔画的地方也写了”。
6. **不能漏白**：写完时字形每个像素都要被遮罩覆盖。
7. 拿不准时查官方写法。thailit.com 的 “How to Write xxx” 页有文字描述，例如 ธ：“Start at the middle left. Draw a vertical line downward, then make a sharp right turn at the bottom … curve it up to the top, finishing with a small upward tail to the right.”

## 五、怎么设计和验证一条路径

靠肉眼估坐标很容易错，实际做法是先把字形栅格化，按像素设计路径，再用程序打分，过关后才写进代码、编译。

### 1. 栅格化字形（务必放正）

用 WPF 的 `GlyphTypeface` 读皮肤里的同一份字体文件 `bin/skin/Sawadee/font/THSarabunNew/THSarabunNew.ttf`，`GetGlyphOutline(glyphIndex, 88, 88)` 取轮廓，画进位图：

```csharp
var geo = tf.GetGlyphOutline(ix, 88, 88);
var bb  = geo.Bounds;
// WPF 字形轮廓本身就是 y 向下（基线上方为负），只平移，不要翻转！
dc.PushTransform(new TranslateTransform(-bb.X, -bb.Y));
dc.DrawGeometry(Brushes.Black, null, geo);
// alpha >= 80 视为笔画像素
```

把每行打印成 `#` / `.` 的字符画，就能看清每一笔的像素范围。

> **踩过的坑**：曾经多做了一次 `ScaleTransform(1,-1)`，得到的字是上下颠倒的。按颠倒的图设计出来的 ธ 路径，在程序里怎么改都“书写顺序不对、空白处也在写”。打印出来的字符画一定要和真实字形对照一遍，确认方向正确。
>
> 另外，判断漏白要用这个**未 hint 的轮廓**，它和程序里 `GetGlyphRunOutline` 的结果一致。不要用 GDI `DrawString` 的结果，GDI 在 88px 下会做 hinting，形状有偏差。

### 2. 按像素写路径，再换算成 0–100

在字符画上沿每一笔的**中线**取点（像素坐标，浮点），再换算：

```
nx = round(px / BW * 100)
ny = round(py / BH * 100)
```

`BW`、`BH` 是轮廓 `Bounds` 的宽高。圆圈要放在圈环的中线上，竖笔放在竖笔列的中间。

### 3. 打分

打分已经做进程序，用的就是界面上的那份字体、轮廓和笔顺。在 `bin` 目录执行：

```bat
Sawadee_mtd.exe --score
Sawadee_mtd.exe --score ธน
Sawadee_mtd.exe --ascii ฮ
Sawadee_mtd.exe --score --ascii ฮ
```

- `--score` 对笔顺打分。后面跟字符就只查这些字，不跟则查笔顺表里的全部字符。全部通过时退出码为 0。
- `--ascii` 把字形印成字符画（`#` 是笔画），用来对照路径点落在哪一笔。
- 带这两个参数时不打开界面。

输出三项，规则和程序运行时一致（半径 = 笔宽 / 2）：

- **离墨采样**：沿每段线段每 0.5 像素采样一次，看笔尖中心是否落在笔画像素上。必须为 0，否则会在空白处写。
- **漏白**：所有笔画像素里，没被任何采样点半径覆盖的个数。必须为 0。
- **折返**：相邻两段方向的余弦值小于 0.2 就记一次掉头，逐个确认是不是字形本身的折角。

不过关就挪点：漏白一般是点离边缘太远，往漏白处挪 0.5–1 像素；离墨一般是取整后点落到了笔画外，把点往笔画中间收一点。

### 4. 写入并编译

- 用新数组替换 `WriteGlyph.cpp` 里对应的那一行（只改这个字）。
- 先结束正在运行的 `Sawadee_mtd.exe`（否则链接会因为文件被占用失败），再执行 `build_clang_ninja_debug.bat`。
- 重启 exe，选中该字观察。

## 六、常见问题对照

| 现象 | 原因 | 处理 |
|------|------|------|
| 没有笔画的地方也写了 | 路径点或连线离开了字形 | 打分时离墨采样必须为 0；两个分开的部分用提笔 `{-1,-1}`，或按字形连通的路线走 |
| 有漏白 | 路径离笔画边缘超过笔宽半径 | 把点挪向漏白处，或在拐角、末端补点 |
| 后面的笔画提前写了一小段 | 遮罩太粗，或路径贴着后写的笔画走 | 让当前路径离开后写的笔画，必要时降低笔宽 |
| 看起来写了几笔 / 来回写 | 路径在同一段上往返，或长距离跳到别处 | 重排顺序，让每段只走一次 |
| 起笔不对 | 没从圆圈或官方起点开始 | 按第四节的规则调整起点 |
| 怎么改都对不上 | 设计用的字形图方向错了 | 确认栅格化没有多翻转 |
| 鼠标不动时笔画停住，鼠标在格子上移来移去才往前走 | 窗口阴影子类化主窗口后 `WM_TIMER` 丢失，只有鼠标消息带来的重画能露出新进度 | 用系统计时队列，不要用 `SetTimer`。见第七节 |
| 写了一小段就卡住，过一会儿整字一下子写完 | 描边很密的字每帧都对整条折线 `Widen`，界面线程被堵住，计时在卡住期间跳走 | 动画用抽稀后的副本，不要改笔顺表。见第七节 |
| 改成贴一张小图后，只有整格重画才看得见墨迹 | 本程序的呈现路径不显示这次 `DrawBitmap` | 墨迹仍用 `PushLayer` 几何遮罩 + `FillGeometry(glyph)` |

## 七、刷新卡住（2026-10 验收）

现象是：笔画自己不走，鼠标在字母格上移来移去才正常；或者写一小段就停，过一会儿整字一下子写完。两件独立的事叠在一起，改绘制解决不了第一件。

### 1. 不能用 WM_TIMER

主窗口带阴影。阴影会子类化这个窗口，之后 `WM_TIMER` 送不到界面。DuiLib 自己的加载圈、轮播、滚动文字都因此改掉了，`UILoading.h` 里写着：用 `CreateTimerQueueTimer`，绕开 Shadow 子类化下 `WM_TIMER` 丢失。

书写动画要同样做：

- `CreateTimerQueueTimer`，首次和周期都是 32ms，回调里 `PostMessage(hwnd, UIMSG_ANIMATION_TICK, 控件, 1)`。
- 主窗口过程把 `UIMSG_ANIMATION_TICK` 转成 `UIEVENT_TIMER`，`CWriteGlyphUI::DoEvent` 里 `wParam == 1` 时 `Invalidate()`。
- 用 `InterlockedExchange` 记住“已经有一条通知在路上”。上一条还没处理完就不要再投，否则消息堆在队列里，画完一帧又立刻被下一帧占住。
- 停写和析构时 `DeleteTimerQueueTimer(..., INVALID_HANDLE_VALUE)`，等回调退出再销毁控件。
- 在 `WM_TIMER` 里再调 `UpdateWindow` 没有用，因为这条消息本身到不了。

鼠标一动就“正常”，是因为鼠标消息会让整格重画，重画时读到的已经是跳过的时间，所以看起来像被鼠标带动。

### 2. 描边太密时不要每帧加粗整条

有些字的笔顺是沿轮廓逐点描的，一条就有几百个点。`BuildWritingMask` 若每 32ms 对“已经写到的整段”做一次 `Widen`，界面线程会卡住。卡住时 `GetTickCount` 仍在走，下一帧的进度已经到 1，字就一下子写完。

处理只发生在动画用的副本 `AnimPath` 里，**不改 `kPaths` 里的笔顺坐标**：

- 真实点数不超过 48 的字，原样使用。
- 更密的字按弧长抽成最多 48 个点，提笔 `{-1,-1}` 仍要保留。
- 不要按“两点直线距离很近就丢掉”。轮廓折返时，近的点可能在笔画另一侧，连过去之后遮罩盖不住字形，画面上就像没有书写动画。

墨迹必须仍是：`Widen` 得到的几何体做 `PushLayer` 遮罩，再 `FillGeometry(glyph)`。不要改成自己画一张位图再 `DrawBitmap`。那张图在这个程序的呈现路径里出不来，只有鼠标引起的整格重画才偶尔看得到。
